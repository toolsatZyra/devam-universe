# Local representational probes — results

**Run date:** 2026-08-07  
**Command:** `python -B research/sarthi-artificial-wisdom/experiments/planner_probe.py`  
**Inputs:** `fixtures.json`  
**External calls or spend:** none  
**Status:** synthetic engineering probes, not product-efficacy evidence

## Purpose

These dependency-free probes test four narrow propositions before any model or database implementation:

1. explicit scope fields can prevent a simple retriever from selecting a semantically close but inapplicable item;
2. a request router can demand the object types a task actually needs;
3. structural case dimensions can reject a lexically attractive but morally irrelevant analogy;
4. clarification can be limited to fields whose plausible values change routing.

They do **not** test Sārthi, an LLM, real embeddings, human judgment, cultural fidelity, or production latency. The fixtures were constructed to make the proposed distinctions observable and therefore cannot estimate real-world effect sizes.

## Interpretation

### P1 — typed scope

The unfiltered lexical baseline chose the wrong lineage record in one of six queries. An exact scope filter eliminated that error. This demonstrates that a scope constraint can matter even in a tiny corpus; it does not demonstrate the magnitude of benefit in real retrieval.

**Design consequence:** make tradition, lineage, location, time, role, and rights/applicability filters available before reranking. Do not infer an unspecified tradition from demographic cues.

### P2 — required object types

For the two fixture queries, generic retrieval omitted one required evidence type, while route-specific requirements covered all expected types.

**Design consequence:** the planner should declare a minimum evidence-type set such as `procedure + applicability + timing + variants` for ritual vidhi. Coverage is a pre-answer diagnostic, not proof that the retrieved objects are correct.

### P3 — analogy and disanalogy

Lexical overlap selected a family-holiday story over the structurally relevant shared-stewardship case. Explicit roles, duties, affected parties, action constraints, and disanalogies reversed the ranking.

**Design consequence:** never use nearest narrative embedding alone for practical guidance. A case must expose transfer dimensions and at least one material disanalogy. The result remains a constructed sanity check; reviewed human scenarios are needed.

### P4 — clarification value

Only four fields changed a route in the supplied counterfactual values. Questions about style or biographical colour did not.

**Design consequence:** ask a clarification only when plausible answers change evidence selection, applicability, safety, or the recommended action. Otherwise continue conditionally.

## What was not learned

- No claim was established that a claim graph, case library, pattern library, or deliberation scaffold beats strong grounded RAG.
- No human reviewer assessed factuality, ritual fidelity, compassion, actionability, or cultural flattening.
- No LLM was tested; there are no current-model capability results here.
- No latency, token, editorial, or operational cost was measured.
- The fixture author knew the intended distinctions, so the tests are not blind and are vulnerable to construction bias.
- The sample sizes are too small for statistical inference.

## Next experiment gate

The next valid comparison is a blinded, same-evidence, same-model trial over held-out scenario **families**:

- A: strong grounded RAG;
- B: A plus material-context and clarification gate;
- C: B plus typed conflicts and the bounded decision record;
- D: C plus reviewed cases/patterns for the slices where they apply.

No layer should be promoted because of these probes alone. Retain it only if it improves a preregistered user-level metric without increasing severe failures, unsupported synthesis, cost, or latency beyond the agreed envelope.
